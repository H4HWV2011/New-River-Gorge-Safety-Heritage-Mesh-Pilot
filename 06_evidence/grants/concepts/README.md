# Grant Development Concepts

This directory contains **early grant-development concepts** under consideration by Harmony for Hope, Inc. in connection with the New River Gorge Safety & Heritage Mesh Pilot, the Community Champion model, Mount Hope implementation, and possible future replication.

These documents preserve ideas at the stage where a potential public-benefit program, funding pathway, demonstration, or transferability model has been developed enough to document and evaluate, but has **not necessarily advanced into detailed program development or a formal grant application**.

---

## Concept Status

The records in this directory belong to the **grant concept** stage of the broader funding-development lifecycle:

```text
funding idea
    ↓
grant concept
    ↓
program / application development
    ↓
submitted application
    ↓
funder review
    ↓
award / decline / revision
    ↓
accepted award and approved scope
    ↓
implementation
    ↓
evaluation
    ↓
closeout
```

A concept may contain substantial detail.

It may describe:

* a community need;
* a target population;
* a possible funding opportunity;
* an implementation idea;
* a proposed budget;
* a demonstration model;
* a transferability strategy;
* a partner role;
* a technology concept;
* or a possible future site.

That level of development does **not** by itself change the document's status.

```text
concept
    ≠
development plan

development plan
    ≠
submitted application

submitted application
    ≠
award

award
    ≠
approved implementation

approved implementation
    ≠
completed outcome
```

Only the stage actually supported by the evidence should be claimed.

---

# What a Concept Does Not Establish

A document in this directory does **not** indicate that the concept has been:

* submitted to a funder;
* reviewed by a funder;
* approved by a funder;
* awarded funding;
* incorporated into the current approved project scope;
* authorized for implementation;
* procured;
* installed;
* launched;
* accepted by a prospective partner;
* accepted by a public agency;
* or demonstrated successfully.

Concept documents are evidence of **development and strategic thinking**.

They are not evidence of implementation authority.

# Current Concepts

The current concept files are:

## `Community Connectivity & Community Champion Demonstration.md`

A working grant concept exploring how community connectivity and the Community Champion model could be combined into a public-benefit demonstration.

The concept helps examine questions such as:

* how technical access and human stewardship might work together;
* how Mount Hope could serve as an initial demonstration environment;
* what a fundable community-facing package might include;
* how residents could be introduced to and supported around new systems;
* and what kinds of evidence a demonstration might generate.

This is a **grant-development concept**.

It should not be read as proof that the described demonstration has been funded or launched.

---

## `Community Champion Transferability.md`

A working concept exploring how lessons from an initial Community Champion implementation could later be evaluated for transfer to another community or site.

Transferability should be treated as an evidence question:

```text
initial implementation
        ↓
field learning
        ↓
evaluation
        ↓
model refinement
        ↓
site-specific review
        ↓
replication decision
```

A model that works in Mount Hope should not automatically be assumed to work unchanged elsewhere.

This concept may inform later grant development, including possible future federal-phase work associated with Thurmond, but it does not establish authorization, funding, or implementation at a future site.

# Mount Hope Boundary

Mount Hope is the New River Gorge Safety & Heritage Mesh Pilot's **initial/current implementation and funding path**.

Concept development may therefore use Mount Hope as:

* an initial demonstration environment;
* a program-development context;
* a place to test community stewardship ideas;
* a grant-development example;
* or the starting point for later transferability analysis.

However:

```text
Mount Hope concept
        ≠
current funded scope
```

The actual current project scope is governed by the current project and budget documents.

Concept files should not silently expand that scope.

---

# Future Federal-Phase Boundary

Thurmond remains a **future federal-phase implementation opportunity, with documented support, contingent on separate federal funding, National Park Service review/compliance, site-specific approval, technical review, and final agreements.**

A concept involving transfer from Mount Hope to Thurmond may explore:

* lessons that could be portable;
* community-engagement methods;
* evidence structures;
* heritage interpretation;
* governance;
* technical possibilities;
* or possible future funding pathways.

It should not be interpreted as evidence that:

* Thurmond implementation has been funded;
* NPS has approved specific equipment;
* a physical installation has been authorized;
* a federal scope has been finalized;
* or Mount Hope's technical architecture may simply be copied onto federal property.

# Relationship to Program Development

A concept may advance into more detailed program or grant-development work.

When that happens, the more developed record should be maintained under:

[`../development/`](../development/)

The development directory contains materials such as:

* program frameworks;
* cohort designs;
* implementation plans;
* budgets;
* timelines;
* training structures;
* and grant-readiness materials.

The original concept should remain in this directory as part of the project's development history.

---

# Relationship to Submitted Applications

When a concept or development framework is adapted into a formal grant application, the submitted version should be preserved separately under:

[`../submitted-applications/`](../submitted-applications/)

The repository should preserve the distinction:

```text
concept
    ↓
development
    ↓
application-specific draft
    ↓
submitted application
```

The submitted application should not overwrite the concept record.

Likewise, the concept should not later be relabeled as “submitted” merely because portions of it were incorporated into an application.

# Community Champion Boundary

Concepts involving Community Champions should preserve the distinction between the **Community Champion model** and the current six-month QA/testing cohort.

The Community Champion model may address:

* community stewardship;
* local facilitation;
* resident support;
* observation;
* field learning;
* documentation;
* leadership;
* and transferability.

The current six-month QA/testing cohort is a separate testing structure composed of:

* one QA/Test Lead; and
* four application/browser testers.

Therefore:

```text
Community Champion concept
        ≠
six-month QA/testing cohort
```

A concept involving Community Champions should not be read as automatically changing the current testing budget or staffing model.

# Concept Development Can Change

Concepts are expected to evolve.

A concept may be:

* revised;
* narrowed;
* expanded;
* combined with another concept;
* moved into program development;
* adapted for a particular funder;
* deferred;
* or retired.

That evolution is part of responsible development.

The repository should preserve enough provenance to show how an idea changed over time.

---

# When a Concept Should Advance

A concept may be ready to move into the `development/` directory when the project begins defining details such as:

* participant roles;
* training;
* implementation sequence;
* staffing;
* compensation;
* evaluation;
* operational responsibilities;
* governance;
* formal budget structure;
* or application-ready program design.

Moving a concept into development does not mean it has been submitted or funded.

It means the idea has become sufficiently mature to support deeper program architecture.

# Evidence and Provenance Principle

This folder is part of the project evidence record.

Its purpose is to preserve **how ideas developed**, not to create the appearance that every idea became a project.

A useful interpretation is:

| Record                  | What It Demonstrates                             |
| ----------------------- | ------------------------------------------------ |
| Concept document        | An idea has been developed enough to evaluate    |
| Development framework   | Program architecture has been explored in detail |
| Draft budget            | Costs have been modeled                          |
| Submitted application   | A formal funding request was made                |
| Award notice            | A funder selected or funded a request            |
| Accepted award          | H4H accepted the award conditions                |
| Approved scope          | Specific activities are authorized               |
| Implementation evidence | Work actually occurred                           |
| Evaluation evidence     | Outcomes were measured                           |

No earlier stage should be used as proof of a later stage.

# Stewardship Principle

Harmony for Hope should be able to explore ambitious ideas without prematurely representing those ideas as funded or authorized work.

The governing principle for this directory is:

```text
explore
    ↓
document
    ↓
evaluate
    ↓
develop if justified
    ↓
submit intentionally
    ↓
implement only when authorized
```

A well-preserved concept archive strengthens the project because it shows not only **what Harmony for Hope wants to build**, but how ideas are tested, refined, funded, governed, and ultimately either advanced or set aside.
