# Submitted Applications

## Read This First

This folder contains **submitted applications** and the supporting materials associated with each submission for the New River Gorge Safety & Heritage Mesh Pilot.

A submitted application is treated as a historical record. Once filed with a funder, partner, program, or review body, its original content should not be silently changed. Corrections, updates, award notices, denials, and later communications should be added as separate dated records.

## Purpose

This area preserves a clear record of:

- What application was submitted
- Which opportunity or funding program received it
- The submission date and deadline
- The version of the narrative, budget, attachments, and forms that were sent
- The person or organization that submitted the application
- The eventual status or decision, when known

## Folder Structure

Create one folder for each submitted application using this format:

```text
YYYY-MM-DD_Funder-or-Program_Short-Application-Name/
```

Example:

```text
2026-09-11_Example-Foundation_NRG-Safety-Heritage-Mesh-Pilot/
```

Each application folder should include, when available:

```text
01_Submitted_Application.pdf
02_Submitted_Budget.pdf
03_Submitted_Attachments/
04_Submission_Confirmation.pdf
05_Follow-Up_and_Decision/
README.md
```

## Required Folder README

Each submitted-application folder should contain a short `README.md` with:

- Application or opportunity name
- Funder, agency, or receiving organization
- Submission date
- Deadline date
- Amount requested, if applicable
- Project title used in the application
- Primary applicant or submitting organization
- Submission method, such as portal, email, mail, or partner submission
- Confirmation number, tracking number, or receipt information
- Current status: submitted, under review, invited to revise, awarded, declined, withdrawn, or unknown
- Links or references to related internal project materials

## Recordkeeping Rules

- Preserve the exact final documents that were submitted.
- Use PDF copies whenever possible for stable recordkeeping.
- Do not overwrite a submitted narrative or budget with later revisions.
- Put drafts and working files elsewhere in the repository.
- Date all follow-up materials and decision notices.
- Remove, redact, or restrict private information before public release.
- Do not publish passwords, portal credentials, bank details, personal addresses, tax documents, or other sensitive material.

## Status Definitions

| Status | Meaning |
|---|---|
| Submitted | Application was delivered or filed, with confirmation when available |
| Under review | The receiving organization has not issued a final decision |
| Invited to revise | Additional information, edits, or a revised proposal were requested |
| Awarded | Funding, support, or approval was granted |
| Declined | The application was not selected or approved |
| Withdrawn | The applicant withdrew the request |
| Unknown | Submission is documented, but the current outcome is not yet verified |

## Notes

This repository may contain public-facing project information as well as internal planning and evidence materials. Before sharing any submitted application outside the authorized project team, review it for personally identifiable information, financial details, partner-sensitive material, and funder-specific confidentiality requirements.
