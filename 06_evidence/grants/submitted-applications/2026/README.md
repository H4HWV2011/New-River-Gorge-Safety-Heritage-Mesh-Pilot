# Year-Level Status Principle

The 2026 index should report only the most specific status supported by preserved evidence.

```text
developed
    ↓
submitted
    ↓
submission confirmed
    ↓
funder review / decision
    ↓
award / decline / revision
    ↓
accepted award
    ↓
approved scope
    ↓
implementation
```

These stages should remain distinct.

```text
submitted
    ≠
awarded

awarded
    ≠
accepted award

accepted award
    ≠
approved scope

approved scope
    ≠
implementation
```

The year index should be updated when later evidence establishes a new status.

---

# Historical Record Rule

Submitted materials should remain the permanent record of what was actually provided to the funder.

A submitted application may later differ from:

* the current project narrative;
* the current master budget;
* later program-development documents;
* later technical architecture;
* later staffing assumptions;
* or later implementation plans.

Those differences should be preserved rather than erased.

The governing principle is:

```text
historical submission
        +
later project development
        =
traceable funding history
```

Do not rewrite an earlier application simply to make it match later project decisions.

---

# Amount Requested Is Not Revenue

Amounts shown in this index represent **funding requested**, unless a later verified record establishes another status.

For the Milan Puskar Foundation application:

**$10,000 requested**

does not mean:

```text
$10,000 requested
        =
$10,000 awarded
```

or:

```text
$10,000 awarded
        =
$10,000 accepted and available
```

Award, acceptance, approved scope, and implementation should each be documented separately when applicable.

# Community Champion Boundary

The September Milan Puskar Foundation application concerns the:

**Mount Hope Community Champion Leadership Pilot**

That submitted Community Champion funding request is separate from the current six-month QA/testing cohort in the broader pilot budget.

```text
Community Champion program
        ≠
five-person QA/testing cohort
```

The Community Champion model addresses community stewardship, leadership, facilitation, resident support, field learning, and related program functions.

The QA/testing cohort is a separate six-month testing structure consisting of one QA/Test Lead and four application/browser testers.

The two may complement one another, but they should not be represented as the same program unless a later approved funding record explicitly combines them.

# Decision Updates

When a funder issues a decision, update the applicable:

```text
month/
└── funder-or-project/
    └── follow-up-and-decision/
```

folder first.

Then update:

```text
application README
        ↓
month README
        ↓
2026 README
```

so that each level reflects the same verified status without replacing the original application record.
